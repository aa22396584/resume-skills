Policy

Privacy

Last updated September 9, 2026

Portable Resume runs entirely on your machine. The project operates no backend, account system, analytics, advertising or telemetry collector. Nothing in the skills, the bundled reader or the installer sends data anywhere.

What the skill reads

When you invoke a resume-<source> skill, the bundled reader opens the local session store that the named coding agent keeps under your home directory, for example Claude Code's ~/.claude/projects JSONL files, Codex's SQLite state and rollouts, Cursor's chat and state databases, Grok Build's session updates, or Gemini CLI's session JSONL. It reads only the sessions that match the current working directory and only within bounded byte and record budgets. It reads other agents' stores; it never modifies them. Reads are stable and no-follow and fail closed when a file changes underneath them.

What it never does

  • It never contacts the network. The shipped runtime contains no HTTP client, socket or remote endpoint.
  • It never invokes the source agent's command-line tool and never restores a live process.
  • It never writes to a source store. The only optional child process is a trusted zstd decoder for compressed Codex rollouts, run with a fixed argument list and an empty PATH.
  • It collects no telemetry, crash reports or usage statistics.
  • It ships no MCP server, credentials, scheduler or background service.

Where the handoff goes

The reader prints the handoff to your terminal, or writes it to a local file you name with --output. That text stays on your machine until you paste it into a new session. Once you do, your host agent (Claude Code, Codex, Grok Build, Cursor or another) sends it to its model provider as part of normal operation, under that provider's policies. Portable Resume does not change that behaviour. Review and trim the handoff before pasting it.

Redaction is best effort

The reader masks common credential shapes (API keys, tokens, private-key headers) before printing. This is best-effort redaction, not complete data-loss prevention: transcripts can contain secrets in shapes the filter does not recognise. Recovered text is labelled untrusted and stale so that you and the destination agent treat it as data, not as instructions.

The installer

install-resume-skills writes only under the skill root you select for a host, keeps an ownership claim and journal there for rollback, and refuses to overwrite files it does not own unless you pass an explicit backup flag. It does not read session stores.

This website

This static site sets no cookies and loads no analytics. GitHub Pages may process and log the requests needed to serve it under GitHub's privacy statement.

Public reports

GitHub issues and pull requests are public. Never attach real transcripts, credentials or absolute home paths. For a security concern, use the private reporting path on the support page.
