Policy

Privacy

Last updated September 9, 2026

Portable Resume runs entirely on your machine. The project operates no backend, account system, analytics, advertising or telemetry collector. Nothing in the skills, the bundled reader or the installer sends data anywhere.

What the skill reads

When you invoke a resume-<source> skill, the bundled reader opens the local session store that the named coding agent keeps under your home directory, for example Claude Code's ~/.claude/projects JSONL files, Codex's SQLite state and rollouts, Cursor's chat and state databases, Grok Build's session updates, or Gemini CLI's session JSONL. It reads other agents' stores; it never modifies them. Reads are bounded by byte and record budgets, are stable and no-follow, and fail closed when a file changes underneath them.

Workspace filtering is source-dependent

The reader passes your current working directory to the source adapter, and adapters whose store records a working directory (Claude Code, Codex, Cursor, Grok Build, Gemini CLI and most others) select only sessions recorded for that directory. This is not a universal guarantee: a session with no recorded working directory stays eligible because the store cannot prove a mismatch, and some sources record no working directory at all, notably OpenHands (its event files carry no directory field, so resume-openhands ignores the directory filter). For those sources, latest can return the most recent session on the machine regardless of project. The handoff header states the source, session identifier and any recorded directory; check it before relying on the content, and use list or an exact session identifier when the workspace matters.

What it never does

  • It never contacts the network. The shipped runtime contains no HTTP client, socket or remote endpoint.
  • It never invokes the source agent's command-line tool and never restores a live process.
  • It never writes to a source store. The only optional child process is a trusted zstd decoder for compressed Codex rollouts, run with a fixed argument list and an empty PATH.
  • It collects no telemetry, crash reports or usage statistics.
  • It ships no MCP server, credentials, scheduler or background service.

Where the handoff goes

The reader itself only prints the handoff to standard output, or writes it to a local file you name with --output. Portable Resume never transmits it. Who then sees that text depends on how you run the reader:

  • Direct terminal use (portable-resume <source> show latest or run_reader.py in your shell): the text stays on your machine until you choose to paste it somewhere.
  • Skill invocation inside a host agent (/resume-claude, $resume-codex and similar): the skill instructs the host to run the reader and read its output as data, so the host agent receives the handoff and sends it to its model provider as part of normal operation, under that host's own privacy terms (Anthropic, OpenAI, xAI, Cursor or another vendor). This happens before you see a summary; there is no manual review step between the reader and the model in that flow.

If a session must not reach a model provider, run the reader directly, review the output, and only then decide what to paste. The handoff also carries a checklist asking the destination agent to summarize rather than repeat recovered text.

Redaction is best effort

The reader masks common credential shapes (API keys, tokens, private-key headers) before printing. This is best-effort redaction, not complete data-loss prevention: transcripts can contain secrets in shapes the filter does not recognise, and during skill invocation whatever survives redaction reaches the host's model provider. Recovered text is labelled untrusted and stale so that you and the destination agent treat it as data, not as instructions.

The installer

install-resume-skills writes only under the skill root you select for a host, keeps an ownership claim and journal there for rollback, and refuses to overwrite files it does not own unless you pass an explicit backup flag. It does not read session stores.

This website

This static site sets no cookies and loads no analytics. GitHub Pages may process and log the requests needed to serve it under GitHub's privacy statement.

Public reports

GitHub issues and pull requests are public. Never attach real transcripts, credentials or absolute home paths. For a security concern, use the private reporting path on the support page.
